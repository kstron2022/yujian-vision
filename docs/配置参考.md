平台的全部可调参数：环境变量、端口、容量、监控与数据保留。部署步骤见 [快速部署](../deploy/README.md) 与 [部署手册](../deploy/部署手册.md)。

## 环境变量（vision.env）

主实例配置放在 `/opt/vision/vision.env`，由 systemd 读取。模板见 `deploy/vision.env.example`。

**必填**

| 变量 | 说明 |
|---|---|
| `MYSQL_USERNAME` / `MYSQL_PASSWORD` | 数据库账号；只授 `vision_platform.*` 权限 |
| `VISION_JWT_SECRET` | 登录令牌签名密钥，至少 32 字符，`openssl rand -hex 32` 生成；换值会让所有人重新登录 |
| `VISION_AES_KEY` | 设备密码、节点 secret、RTSP 地址的加密密钥，至少 32 字符；更换前先做密钥轮换（见下文） |
| `VISION_ALERTWEBHOOKTOKEN` | 告警回调令牌，至少 16 字符；接了监控栈时与 Alertmanager 配置同值 |

**常用**

| 变量 | 默认 | 说明 |
|---|---|---|
| `SERVER_PORT` | 8082 | 平台监听端口 |
| `REDIS_DB` | 1 | Redis 逻辑库，选现场空闲的 |
| `SPRING_DATA_REDIS_PASSWORD` | 空 | 有密码的 Redis 才设置，无密码不要写空串 |
| `LOG_DIR` | `./logs` | 日志目录 |
| `VISION_SNAPSHOT_DIR` | `./data/snapshot` | 抓图落盘目录，需预先创建 |
| `VISION_SECURITY_TRUSTEDPROXIES_0` | 空 | 反向代理到平台的源地址，支持 CIDR；配错会导致限流和审计失真 |
| `VISION_WEBUI_EMBEDDED` | 自动 | 是否启用 jar 内置前端（构建时带 `web-ui/dist` 即自动开启）；设 `false` 改为 Nginx 托管 |
| `VISION_GB_SERVERID` / `VISION_GB_DOMAIN` / `VISION_GB_REALM` | 打包默认 | 国标编码、域、realm，按现场分配修改 |
| `VISION_ONVIF_DISCOVERY_INTERFACE_IP` | 内核选路 | 多网卡机器必须指定业务网卡 IP，否则设备发现永远无结果 |

**容器化专属**

| 变量 | 说明 |
|---|---|
| `VISION_SIP_PUBLIC_IP` | 宿主对外 IP。不配会宣告容器内网地址，设备按 Via 回包后立即断连 |
| `VISION_PLAY_PUBLIC_BASE` | 对外播放地址前缀，如 `http://192.168.1.10:8081`；不配则用节点内网地址，播放黑屏 |
| `SERVER_ADDRESS` | 平台绑定地址；主备同机时必须显式指定，不能绑定 `0.0.0.0` |

compose 形态另有一份 `.env`（MySQL/Redis 口令、端口、RTP 段），由 `setup.sh` 自动生成，一般不需要手工改。

## 端口

| 端口 | 用途 |
|---|---|
| 8090 | 前端入口（容器化；裸机按 Nginx 配置） |
| 8082 | 平台 REST API、WebSocket、Hook 回调 |
| 5060 tcp+udp | SIP 信令 |
| 30000-30500 tcp+udp | RTP 收流，段大小等于最大并发收流路数 |
| 8081 | ZLM HTTP（API、FLV、TS、HLS） |
| 554 / 1935 | ZLM RTSP / RTMP |

改 RTP 段要同时改三处：`config.ini` 的 `rtp_proxy.port_range`、`.env` 的 `ZLM_RTP_START/END`、平台节点配置。

## 容量参考

| 项 | 建议 |
|---|---|
| CPU / 内存 | 最低 4C8G（小规模，控制并发）；5000 通道 / 200 路压测口径为 8C16G 起；参考机型 16C16G |
| 系统盘 | 100G（程序、日志、抓图；抓图有上限并每日自动清理） |
| 通道数 | 单机 5000 通道内做过压测 |
| 并发点播 | 200 路以内做过压测，超过后按 ZLM 带宽和 CPU 追加 |
| 录像盘 | 按码率 × 时长 × 路数估算；设备侧录像（NVR）不占平台盘 |

## 主备高可用

| 变量 | 说明 |
|---|---|
| `VISION_HA_ENABLED` | `true` 启用；不配与单机完全一致 |
| `VISION_HA_ROLE` | `active` / `standby` |
| `VISION_HA_TOKEN` | 实例间内部接口令牌，两实例同值 |
| `VISION_HA_PEER_BASE_URL` | 对端地址，如 `http://127.0.0.1:8083` |
| `VISION_SIP_AUTOSTART` | 备实例设 `false`，接管时才绑定 5060 |

## 监控

平台自身暴露 Prometheus 指标：`GET http://<平台IP>:8082/actuator/prometheus`。
需要开箱即用的看板、告警规则与站内消息联动，可用 [deploy/monitoring/](../deploy/monitoring/) 的旁路监控栈（Prometheus + Alertmanager + Grafana + node-exporter，四容器，全部内网）。
不部署监控栈不影响平台任何功能。

## 密钥轮换

`VISION_AES_KEY` 用于解密库里已有的设备密码和节点 secret。平时不需要轮换，只有密钥疑似泄露或合规要求时才做：

1. `openssl rand -hex 32` 生成新密钥。
2. `vision.env` 里改 `VISION_AES_KEY=<新值>`，临时加一行 `VISION_AES_OLD_KEY=<旧值>`。
3. 重启平台，看启动日志：`设备密码 加密 0 轮换 N (失败跳过 0)`，失败跳过应为 0。
4. 登录、点播各验一次（Digest 认证和 URL 签名都会用到解密）。
5. 删除 `VISION_AES_OLD_KEY` 再重启。

直接改新密钥而不配 `OLD_KEY`，存量密文全部解不开，设备认证和播放签名都会失败。

## 数据保留

| 数据 | 默认 | 配置 |
|---|---|---|
| 云端录像 | 30 天 | `vision.retention.cloud-record-days` |
| 软删记录物理清理 | 30 天 | `vision.retention.soft-delete-days` |
| 抓图文件 | 按通道上限 | 每日 02:50 清理孤儿文件 |
| 录像清理任务 | 每日 02:40 | — |

录制跟随实况流：只有通道在计划时段且有观众时才会向 ZLM 发起录制。
